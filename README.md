# CS 보이는 코드

코드만 봐서는 감이 잘 안 오는 CS 개념을 **줄 단위 실행 애니메이션**과 **성능 수치**로 보여 주는 학습 사이트입니다.
느린 코드와 빠른 코드를 나란히 놓고 같은 속도로 실행해서, 어느 줄이 몇 번 실행되고 그 결과 비용이 어떻게 벌어지는지 눈으로 확인합니다.

## 실행

빌드 과정이 없습니다. `index.html`을 브라우저로 열면 됩니다.

```bash
npx serve .        # 또는 python3 -m http.server
```

정적 파일뿐이라 GitHub Pages 같은 정적 호스팅에 그대로 올릴 수 있습니다.

글꼴은 Pretendard(jsDelivr)와 JetBrains Mono(Google Fonts)를 불러옵니다. 불러오지 못하면 시스템 글꼴로 표시됩니다.

## 네 가지 사용법

**1. 개념부터 배우기** — 왼쪽 목차에서 레슨을 따라갑니다. 목차는 **분야별**(알고리즘, 자료구조, 언어·런타임, 네트워크, DB, 인메모리·캐시, 동시성, 분산, AI)로 접고 펼 수 있고, 위의 칩으로 **난이도**(기초·중급·심화·시니어)를 걸러 볼 수 있습니다.

**2. 증상에서 출발하기** — 디버깅 중 본 현상으로 원인을 찾습니다. 왼쪽 위 **증상으로 찾기**에서:

- 원인을 좁히는 순서 (현상을 숫자로 → 입력 크기와의 관계 → 바쁜 자원 → 가설 검증 → 재측정)
- 1차 분류표: "CPU는 낮은데 느리다", "메모리가 계속 오른다", "AI 답이 매번 다르다" 같은 관찰로 영역 좁히기
- 증상 사전: 현상 → 의심할 CS 개념 → **확인 방법(무엇을 재면 확신할 수 있는가)** → 고치는 방향 → 해당 레슨

**3. 면접 · 코딩 테스트 대비** — 왼쪽 위 **면접 · 코테 대비**에서:

- 입력 크기로 허용 복잡도를 가늠하는 표 (n ≤ 20이면 O(2ⁿ), n ≤ 100만이면 O(n log n) …)
- 문제 문장의 신호로 유형을 고르는 표 ("연속 부분 배열" → 슬라이딩 윈도, "같은 그룹인가" → 유니온 파인드 …)
- 면접 질문 은행: 분야별 필터와 검색, 답을 가린 채 먼저 말해 보고 펼쳐 확인, "답할 수 있음" 자기 채점과 진도, 못 푼 질문 무작위 뽑기

**4. 코테 실전 훈련** — 왼쪽 위 **코테 실전 훈련**에서 코드를 쓰기 전에 방향을 잡는 연습을 합니다.

- 문제 20개(쉬움·보통·어려움). 문제와 제한을 읽고 세 가지를 고릅니다: **허용 복잡도 · 접근(알고리즘) · 핵심 자료구조**
- 채점하면 항목별로 ✓(대표 풀이) · △(다른 풀이로 인정) · ✕(오답)와 **그 선택이 왜 안 되는지**를 알려 줍니다
- 이어서 사고 과정(무엇을 보고 그 유형이라고 판단하는가), 입력 크기별 연산 횟수 어림, 풀이 뼈대 코드, 자주 틀리는 곳, 관련 레슨을 보여 줍니다
- 판단 시간(목표 3분)을 재고, 첫 시도 기준 정답률과 다시 볼 개념을 모아 줍니다. 막히면 문제에서 눈여겨볼 표현을 표시할 수 있습니다
- **사고방식 · 팁** 탭: 문제를 받았을 때의 5단계 루틴, 유형이 안 떠오를 때 던질 질문, 엣지 케이스 점검표, 시간 관리, 디버깅 순서, JavaScript 주의점, 라이브 코딩 요령

각 레슨 아래에도 그 주제의 면접 질문, 코딩 테스트 포인트(해당하는 경우), 증상 상자가 있습니다.

### 비유로 푼 레슨 (시범)

숫자 배열 대신 친숙한 상황으로 설명하는 레슨입니다. 코드와 용어는 그대로 두고 데이터와 설명 문장에만 이야기를 입혔고, 레슨 아래 "비유로 다시 보기"에 이야기 ↔ 실제 용어 대응표와 비유가 맞지 않는 부분을 적었습니다.

- 선형 탐색 vs 이진 탐색 → 업다운 숫자 맞히기 게임
- 힙(우선순위 큐) → 응급실 접수
- BFS vs DFS → 미로 게임에서 출구 찾기

레슨에 `story: { scene, map: [[이야기, 실제 용어], ...], limit }`를 넣으면 대응표가 표시됩니다.

## 화면 읽는 법

- **노란 줄**: 지금 실행 중인 코드
- **줄 왼쪽의 붉은 막대와 `×N`**: 그 줄이 실행된 횟수 (뜨거울수록 병목)
- **줄 오른쪽 꼬리표**: 그 줄이 성능에 주는 영향
- **아래 그림**: 그 줄이 메모리/자료구조를 어떻게 바꿨는지
- **맨 위 점수판**: 두 방식의 지표를 같은 눈금으로 나란히 비교
- 머리말 아래 문장: 진행 중에는 소개, 끝나면 결론

### 보기와 재생

- 머리말·점수판·두 카드가 스크롤 없이 한 화면에 들어옵니다. 공간이 모자라면 그림을 자동으로 축소하고, 코드는 실행 중인 줄을 따라 스크롤합니다.
- **나란히 / 하나씩**: 두 방식을 동시에 보거나, 한 방식씩 크게(코드 왼쪽·그림 오른쪽) 봅니다. 작은 화면에서는 "하나씩"이 기본이고, 이때 점수판은 다른 방식의 최종 결과를 기준선으로 보여 줍니다.
- `☰`로 목차를 접으면 무대가 넓어집니다.
- **헤더는 화면 위에 고정**되어, 아래 정리 영역으로 스크롤해도 제목과 조작 버튼이 남습니다.
- **반응형 3단계**: 넓음(1025px~)은 목차가 옆에 고정, 중간(761~1024px)은 목차가 서랍으로 들어가고 무대는 한 화면 유지, 좁음(~760px)은 카드가 세로로 쌓이고 헤더·점수판·플레이어만 고정됩니다.
- **자동 재생은 읽는 속도에 맞춥니다.** 새로 나온 설명의 글자 수만큼 기다렸다가 넘어갑니다. 아래 조작 독에서 속도(느리게·보통·빠르게·훑기)를 고르고, 남은 예상 시간과 각 방식이 끝나는 지점(진행 막대 위의 점)을 볼 수 있습니다.
- `Space` 재생/정지, `←` `→` 한 단계씩, 슬라이더로 이동, 일부 레슨은 입력 크기 n 변경 가능

## 레슨 추가하기

레슨은 실제 알고리즘을 실행하면서 `t.step(줄 번호, 설명, 패널들)`로 매 순간을 기록합니다. 줄별 실행 횟수와 지표 막대는 자동으로 만들어집니다.

```js
CS.add({
  id: 'my-lesson', level: 'basic',            // basic | mid | adv | senior
  title: '제목', summary: '한두 문장 소개',
  headline: '비교 횟수',                       // 끝났을 때 크게 비교할 지표
  verdict: '결론 한 줄',
  variants: [{
    name: '느린 방식', tone: 'bad',            // bad | good | info
    big: { time: 'O(n)', space: 'O(1)' },
    code: `...`, notes: { 2: '이 줄의 비용' },
    run(t, n) {
      t.m['비교 횟수'] = 0;
      t.step(1, '설명', [{ type: 'cells', title: 'arr', items: [{ id: 0, v: 1, s: 'active' }] }]);
    },
  }],
  points: ['핵심 정리'], senior: '시니어 관점',
  // 아래는 레슨과 함께 적는 부가 정보
  topic: 'algo',                               // 목차 분야: algo | ds | lang | net | db | mem | conc | dist | ai
  qa: [['면접 질문', '답의 뼈대']],              // 면접 질문 은행에 들어간다
  dx: { cat: ['slow'], concept: '의심할 개념', symptoms: ['디버깅 중 보게 되는 현상'],
        check: '무엇을 재면 확신할 수 있는가', fix: '고치는 방향' },   // 증상 사전 (선택)
  ct: { signal: '문제에서 보이는 신호', how: '접근', big: 'O(n)', trap: '자주 틀리는 곳' },  // 코테 유형표 (선택)
});
```

패널 종류: `cells`(배열/막대/격자), `stack`, `buckets`, `graph`(트리·참조 그래프), `timeline`.
새 파일을 만들었다면 `index.html`에 `<script>`를 추가하세요.

`dx.cat`은 `slow | hang | memory | wrong | flaky | data | crash` 중에서 고릅니다. 초기 레슨들은 같은 정보를 `js/prep.js`(분야 · 면접 질문 · 코테 유형)와 `js/symptoms.js`(증상)에 레슨 id로 모아 두었고, 두 방식은 함께 동작합니다. 훈련 문제는 `js/drill.js`의 `D.problems`에 추가합니다(형식은 파일 위 주석 참고).
